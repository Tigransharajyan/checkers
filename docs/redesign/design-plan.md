# Checkers Online — материалы независимого дизайн-ревью, v1
Дата: 6 ноября 2026. Статус: спецификация, код приложения ещё не изменялся.

## 1. Продукт и пределы наблюдения
Существующее приложение русских шашек 8×8, не SaaS и не маркетинговый лендинг. Аудитория предположительно: любители, начинающие и возвращающиеся игроки; настоящих интервью/аналитики нет. Основные задачи: начать онлайн-партию, тренироваться с ботом (3 уровня), создать/принять приглашение, решить ежедневную задачу, просмотреть сохранённые партии и процент побед, узнать правила.
Стек: Java 17 target (локально JDK21), Spring Boot 3.3.4, Thymeleaf, JWT access/refresh, H2 dev/Postgres prod, STOMP/SockJS, vanilla JS, локальные Inter variable + Noto Sans Armenian + Lucide. Существующие маршруты: / и /index, /play (меню или партия ?id=), /tasks, /rating, /history, /faq, /login, /register. EN/RU/HY; только тёмная тема, переключателя тем нет. Не добавлять вторую тему в этом редизайне. На широком экране сохранять ограниченную ширину, а не растягивать доску.
Общие шаблоны sidebar/mobile nav/head/assistant. CSS: design-system.css 329 строк, app.css 4149 строк с повторными слоями, theme.css 403 строки с переопределениями. Единого владельца правил нет. Шрифты и лицензионные файлы уже локальны. Фото checkers-hero.webp и login-board-scene.png: происхождение не установлено, исключаются из UI; не заявлять, что они сгенерированы.
Движение: переходы кнопок, pulse/свечение, анимация фигур, drag/drop, premove, SVG-аннотации. Последние четыре — полезная функциональность, сохранить. Доска уже поддерживает стрелки и Enter/Space с roving tabindex; сохранить и проверить. Сохраняются API, auth, SEO, языковые URL, правила и данные. Backend/БД не рефакторить.

## 2. Проверки исходного интерфейса
Локальное приложение реально запущено http://localhost:8080. Playwright Chromium: восемь маршрутов + настоящая партия с ботом на 1440/1280/768/390/360/1920; 55 PNG в /tmp/checkers-redesign/before. Все три языка будут полной матрицей проверены после реализации; исходный визуальный аудит в RU, поддержка EN/HY также изучена в коде. Светлой темы не было. Документная ширина исходных 48 состояний не превышает viewport — не выдумывать исходное переполнение.
Фактически проверены: гостевой запуск бота, начало/отмена matchmaking, поиск FAQ (дамка: 2 совпадения), пустая auth-форма, drawer Escape. По коду и тестам изучены приглашения, сдача/ничья, задачи, история. Проверка реального матчмейкинга двух независимых посетителей и backend suite — в итоговом QA. Исходный drawer не закрывается Escape, aria-expanded отсутствует; поля ошибок без aria-invalid/aria-describedby. Скриншоты референсов ниже тоже реальные, не только web-текст.

## 4. Исследование семи реальных интерфейсов
Все страницы открыты Chromium 1440×1000, скриншоты и текст в /tmp/checkers-redesign/research. Это эвристический анализ доступного UI, не UX-исследование пользователей.
1. https://lidraughts.org/ — рабочее лобби: основные игровые действия сгруппированы отдельно, puzzle содержит реальную позицию. Применяем игровую иерархию/position preview. Не переносим турниры и контроль времени: этих функций нет.
2. https://lichess.org/training — настоящая доска занимает центр, условие рядом, нейтральная оболочка и компактная нотация. Применяем board-first game и соседство статуса с доской; не копируем шахматные фигуры/оценочную шкалу.
3. https://www.chess.com/play/computer — в доступном UI видно board/sidebar и onboarding modal «Play the bots» с Start; личности ботов и уровни раскрываются рядом с доской. Применяем явное название действия и выбор сложности перед стартом. Не переносим платные bot persona/яркую бренд-палитру. Не утверждаем прохождение игры на внешнем сайте.
4. https://online-go.com/observe-games — реально загруженная галерея партий: доски с короткой информацией, последовательная сетка. Применяем принцип «реальная позиция важнее обложки». Массовую галерею не добавляем: у проекта нет просмотра чужих игр.
5. https://www.playok.com/en/checkers/ — доступная страница входа: сразу два пути login/guest, конкретная разновидность игры. Применяем отсутствие обязательной регистрации до партии, ясное название правил. Малый шрифт и рекламные блоки неприменимы; внутреннее лобби за login не изучено.
6. https://design-system.service.gov.uk/components/text-input/ и /error-message/ — реальные рабочие примеры: видимый label, ошибка у поля, сохранение значений. Применяем label/aria/focus/errors, не британский государственный branding и не отдельный экран на каждое поле.
7. https://playstrategy.org/ — реальное multi-game lobby с основным Start a game и библиотекой вариантов отдельно. Применяем разделение начала игры и обучения. Не добавляем визуальный каталог вариантов/форум, поскольку приложение только про русские шашки.
Синтез: предметный старт игры, доска как единственное необходимое изображение, малая конкуренция акцентов, прямые подписи действий, комфортные формы.

## 5. Три самостоятельных направления
### A. Шашечный клуб — рекомендуется
Идея: спокойный настольный клуб, доступный новичку, уверенный игроку. Тёплая светлая рабочая область и глубокая зелёная вертикальная навигация. Настроение тактильное, собранное, без фото и имитации материалов.
Палитра: canvas #F5F2EB, surface #FFFEFA, ink #242B27, secondary #59645D, pine #245746, pine-hover #1A4436, sidebar #183D32, line #D9DDD3, board light #F0DFC0/dark #8B6245, ochre #A56C27 только небольшие state/board details.
Типографика: системная Georgia для больших h1/бренда, Inter для UI; Noto Sans Armenian для HY (заголовки HY без неподдержанного serif fallback), 40/32/24/20/18/16/14. Без uppercase микротекста.
Композиция: sidebar 208px, max content1184px, 32px поля; home 1fr+300px, основной онлайн-блок, вторичные bot/friend строки, join ниже, реальная daily board справа; история ниже. Главная не повторяет маркетинговый hero. /play меню переиспользует выбор режима. /game — доска + компактные controls. /tasks — доска/инструкция. /rating — одна полоса 3 метрик и процент, /faq — текстовые строки.
Компоненты: 6–8px радиусы, тонкие разделители, ровные кнопки; нет одинаковых карточек на всё. Интерактивность 160ms цвет, сохранённая meaningful motion фигур до ~200ms, reduced-motion.
Плюсы: ясная основная задача, сильное отличие от neon-dark shell, подходит всем языкам и привычной настольной игре. Риски: светлая тема непривычна существующим пользователям; serif не в мелких контролах; brown board требует контраста фигур и state outlines. Смена единственной темы осознанная, без добавления settings.
### B. Турнирный стол
Идея: плотный инструмент для регулярной игры. Graphite #222725, panel #303733, text #F4F3E9, muted #B9C4BD, copper #D6AB67, action #326E59, line #57625C. Только сплошные заливки.
Типографика: полностью Inter/Noto, h1 28/32, UI16, notation tabular14. Верхняя горизонтальная навигация 64px вместо sidebar; canvas максимум1360, поля24, шаг8. Lobby — компактная таблица режимов с controls справа, задачи под ней; game — большая доска и 280px нотация. Mobile верхний menu и нижние 4 основных ссылки. Компоненты угловатые 4px, grouped toolbar, state underline/icon; только короткая подсветка.
Плюсы: профессиональный игровой инструмент, знакомый dark mode, максимальная плотность. Риски: слабее обучающий контекст, длинные RU/HY labels перегружают верхнюю навигацию; ближе к существующим chess сервисам. Сильная альтернатива для аудитории с подтверждённым регулярным использованием.
### C. Школа комбинаций
Идея: игра через практику, editorial learning workspace. Canvas #FFFFFF, ink #182D42, navy #203E59, panel #EEF3F5, action terracotta #A94932, line #CCD8DE, board #E2D6C0/#667A85.
Типографика: Noto/Inter крупные h1 36 semibold и 18px основной текст, без serif. Сетка12 колонок, max1120, gap24, отступы12/24/36. Навигация узкая горизонтальная, внутри tasks/context вертикальное оглавление; home split с ежедневной задачей слева и компактным стартом игры справа. FAQ — тематические группы на одной странице с search, auth одна колонка. Компоненты открытые секции, встроенные подсказки, state иконка+текст. Mobile задача перед игрой и собственный practice CTA; короткие раскрытия подсказок.
Плюсы: лучшая поддержка начинающих, сильная индивидуальность учебного продукта, комфортный длинный текст. Риски: ежедневная задача начинает конкурировать с основной игрой; потребовалась бы проверка реальной аудитории и больше контента. Нельзя заявлять наличие уроков, которых нет.
Выбор A: сохраняет главную игровую миссию без превращения продукта в турнирный терминал или учебный портал. Улучшает A1–A15 и не предполагает новые backend функции.

## 6. Полная спецификация A, v1

Контраст всех окончательных пар проверить вычислением и axe, цель normal4.5/large3/UI3. Тёмный/светлый outline доски комбинированный, читаемый на обоих полях. Accent white на pine. Borders input #7C887E; divider #D9DDD3 только декоративное разделение. Disabled сохраняет текст, без pointer.
Основной text16/1.55, small14/1.45; h1 Georgia40/1.15 desktop32 mobile, h2 Inter22/1.3, h3 18/1.35. HY Noto, h1 34 desktop/28 mobile, без letter spacing. Контент текста65ch. Вес400/500/600/700; цифры tabular. Шаг4, разрешены8/12/16/20/24/32/40/48; primary controls48px, compact44px, icon44px. Radii4 input,6 button,8 panel, circle только фигуры/avatar. Граница1px, board2px. Тень только neutral на dialog/drawer, без цветных теней/blur.
Breakpoints: <=600 one-column controls, <=900 drawer вместо sidebar + mobile top56/bottom68safe; >=1040 lobby grid; промежуточные ширины последовательные. Desktop sidebar208, content padding32 (24 tablet/16 mobile), max1184 центр в оставшейся ширине. Wide1920 центрировать, не растягивать. 200% text/reflow и 320px проверить.
Icons existing Lucide20/24, stroke2, labels видимы, декоративные aria-hidden. Без новых зависимостей/изображений.
