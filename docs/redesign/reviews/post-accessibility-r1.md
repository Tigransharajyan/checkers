## Три наиболее сильные стороны

1. **Доска стала семантически корректной и управляемой.** Лично полученный AX snapshot содержит grid → row → gridcell, включая координаты/цвет и «может ходить». Доска связана с видимой инструкцией через `aria-describedby=board-instructions`. До gridcell `a1` можно дойти Tab, затем стрелками выбрать фигуру, Enter сделать ход. В проверенном сценарии после хода фокус остался в `f6`.
2. **Формы сообщают ошибки содержательно.** На screenshot ошибки не зависят только от красной рамки. В собственном браузере пустой submit установил `aria-invalid=true`, сохранил `aria-describedby=usernameOrEmail-error` и перевёл фокус в первое ошибочное поле. Текст labels/подсказок читаемый, primary имеет достаточный базовый контраст.
3. **Мобильная структура заметно удобнее исходной.** У режимов подписанные действия, у задачи условие перед доской, у истории явная инструкция горизонтальной прокрутки внутри контейнера. Fixed bottom nav на полноэкранном screenshot не считаю доказательством недоступного контента: есть прокрутка и конечный отступ. Escape действительно закрыл drawer и вернул фокус trigger.

## Блокирующее замечание

### POST-AX1 — High: успешный промежуточный ход задачи не вызывает никакого live-объявления

Фактически воспроизвёл первый правильный ход клавиатурой: `g5–f6`, автоматический ответ чёрных `e5:g7`, ответ сервера `ACTIVE`. Результат:

- прогресс в DOM стал «Ходы: 1 / 4»;
- focus сохранился на `f6`;
- `[data-task-feedback]` остался пустым и `hidden`;
- MutationObserver на всех `[role=status],[aria-live]` не зарегистрировал ни одного обновления;
- grid вернулся из busy в `false`, но сама grid правильно не является live-region.

Таким образом, пользователь клавиатуры/AT получает реакцию на ошибку или финальное решение, но при правильном промежуточном ходе не получает содержательной информации, что ход принят и компьютер уже ответил. Для изучения последовательности приходится заново исследовать клетки. Это центральный сценарий продукта и прямой пробел в предусмотренном отдельном polite status.

**Исправление:** после обработки событий одного принятого хода обновлять один постоянный `role=status`/`aria-live=polite` (можно существующий feedback) локализованной короткой строкой: «Ваш ход g5–f6. Чёрные e5:g7. Ваш ход. Ходы: 1 / 4». Нотацию брать из реальных response.events, текст хода/ходящего — из локализации. Не делать live всю доску, не переводить focus, не прокручивать страницу автоматически, не объявлять каждую промежуточную animation frame. Итог success/error оставлять как сейчас с предметным сообщением. Проверка должна подтвердить одно содержательное обновление live-region после принятого ACTIVE-ответа и сохранённый focus. Отдельно объявлять load error через status, сохраняя Retry.

## Другие конкретные замечания

### POST-AX2 — Medium: backdrop drawer получает inert и не закрывает панель при внешнем нажатии

В открытом drawer `[data-sidebar-backdrop].inert === true`; helper делает inert всех siblings, включая backdrop. Нажатие мышью по внешней области x385/y300 оставило `sidebar-open overlay-open`. Escape и внутренняя close-кнопка дают рабочий путь выхода, поэтому это не ловушка клавиатуры и не самостоятельный accessibility-блокер, но заявленное закрытие backdrop нарушено.

Исправление: backdrop должен оставаться pointer-active, но не становиться фокусируемым/видимым для AT; исключить его из inert списка либо разместить его в modal branch, сохранив inert main и bottom nav. Проверить реальное внешнее нажатие после завершения открытия. Тот же принцип проверить у других modal backdrops.

- В desktop game на screenshot между статусом и собственной карточкой игрока много вертикального пространства. Само по себе не блокер: помогает сопоставлению с доской, но статус/управление не следует дополнительно раздвигать.
- В полноэкранных mobile снимках временный toast «Подключено» перекрывает имя игрока. Это ограниченное по времени сообщение, не считаю критическим, но полезно заменить повторяющиеся connection toasts устойчивым кратким статусом только при изменении соединения.
