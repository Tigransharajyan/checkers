# Независимое ревью AGENT 4 — Accessibility & Usability, раунд 1

Материалы: полностью прочитан `design-review.md` v1; реально просмотрены `before/home-1440.png`, `before/play-390.png`, `before/tasks-768.png`; прочитаны релевантные участки `board.js` и `tasks.js`. `before/axe.json` на момент обращения отсутствовал. Реализацию редизайна не видел и не тестировал. С другими ревьюерами не общался, их заключения не читал.

## Три сильные стороны

1. План обращается к конкретной трудности чтения: увеличивает подписи до 14px и основной текст до 16px, сохраняет локальную поддержку кириллицы и армянского, ограничивает длину ответов FAQ. Это соответствует наблюдаемым мелким подписям на исходных экранах.
2. Действия получают постоянные видимые названия, а ошибки — связь с полями и фокус на исправлении. Снятие клика со всего article устраняет неоднозначную псевдокнопку с вложенным select.
3. Предусмотрены безопасный начальный фокус в диалогах, return focus, inert, reduced motion, честные состояния загрузки и запрет перекрывать доску плавающим помощником. Это существенно лучше исходного поведения.

## Критические замечания к плану

### AX1 — High: семантическая структура и озвучивание доски оставлены условной задачей

В `board.js` фактически `role=grid` содержит 64 непосредственных `role=gridcell`, без `row`. Следовательно, это не только гипотетическое «проверить и исправить, если нужно». Кроме того, aria-label клетки сейчас передаёт координату/цвет/дамку, но не передаёт обязательность взятия или доступную клетку назначения. Визуальный dot/ring сам по себе недоступен невидящему пользователю. Сохранение стрелок и Enter полезно, но недостаточно, чтобы человек мог понять, куда и почему сделать ход.

Исправление спецификации: прямо включить корректную модель grid → 8 row → 8 gridcell (или другой заранее выбранный корректный интерактивный паттерн), сохраняя существующие DOM-узлы клеток и движок. Для grid задать строку/колонку, а для клетки — координату, фигуру, selected и доступные состояния: «может ходить», «обязательное взятие», «доступный ход/взятие». Дать связанную через aria-describedby краткую инструкцию клавиатуры на всех языках. О ходе игрока/ответе/ошибке сообщает отдельный короткий polite status; не делать всю доску live-region. Критерий приёмки — валидная структура, реальный ход с клавиатуры без мыши, стабильный фокус на сохранённой клетке после обновления.

### AX2 — High: жизненный цикл modal drawer не определён при смене breakpoint и для видимой кнопки закрытия

План правильно требует inert/trap, но не фиксирует кнопку закрытия внутри drawer и восстановление inert/скрытого состояния при переходе из mobile в desktop. Существующий toggle находится вне sidebar; если фон с ним inert, повторное нажатие недоступно. Существующий resize-порог 768px (1200 для game), а новый общий — 900px: это явный источник несогласованности. Необходимо спроектировать это до реализации.

Исправление спецификации: внутри drawer постоянная подписанная close-кнопка >=44px; modal trap и inert действуют только при открытом мобильном drawer. Закрытый drawer не попадает в Tab/AX tree. На resize в desktop очистить trap/inert/scroll lock и показать sidebar обычной nav; при обратном переходе закрыть drawer и не оставлять фокус в скрытой панели. Возврат фокуса — к видимому trigger, а при его исчезновении к main/логичному nav-элементу. Единый matchMedia-порог используется и CSS, и JS; game явно 1200px. Проверить цикл open → resize desktop → resize mobile → Tab/Escape.

## Дополнительные конкретные улучшения (не отдельные блокеры)

- Для overflow таблицы в history предусмотреть `tabindex=0` на самом прокручиваемом контейнере, accessible name и короткую подсказку, когда прокрутка действительно есть. Иначе «scroll внутри контейнера» не гарантирует доступ к последнему столбцу с клавиатуры.
- План говорит про формы, но также нужны ошибки auth/API в правильном контексте: запрос не удался → form status, неверное поле → error рядом с ним; busy должен блокировать оба конкурирующих пути submit/guest и восстанавливаться при ошибке.
- После reset/ответа задачи не переводить фокус автоматически и не делать экран внезапно прокручиваемым. Условие перед доской полезно, но feedback выше доски может быть за viewport после длинного хода; live status должен сообщать результат, а состояние — оставаться доступным при прокрутке.
- Добавить проверку `forced-colors`: rings/crown/outline и focus остаются видимыми без фонового цвета. Это особенно полезно доске и не требует новой темы.
- Статус соединения/очереди не должен озвучиваться непрерывно при каждом polling. Announce только при изменении смысла.

## Проверка заявленных цветовых пар

Вычислил WCAG relative luminance из указанных HEX, без браузерных предположений:

| Пара | Контраст |
|---|---:|
| #59645D на #F5F2EB | 5.52:1 |
| #245746 на #FFFEFA | 8.24:1 |
| #126A85 на #F5F2EB | 5.48:1 |
| input border #7C887E на #FFFEFA | 3.66:1 |
| #126A85 на board-dark #8B6245 | 1.15:1 |
| #F0DFC0 на board-dark #8B6245 | 4.08:1 |
| ochre #A56C27 на #F5F2EB | 3.93:1 |

Основные пары выглядят обоснованно. Focus на доске нельзя применять только синий: предписанная двойная светлая/тёмная окантовка необходима. Ochre не использовать как обычный 14–16px текст на canvas. Фигуры и состояния требуют отдельных окончательных пар: не считаю их проверенными.

## Вердикт: CHANGES REQUIRED

Направление A одобряю по смыслу и базовым цветам. До Design Approval Gate требуется уточнить AX1 и AX2 в спецификации. Это небольшие, но принципиальные условия: главный инструмент продукта должен быть семантически понятен, а адаптивная навигация — предсказуемо доступна. Реализацию для принятия плана не требую; после уточнений готов к независимому повторному ревью.
